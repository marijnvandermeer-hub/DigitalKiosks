# Digital Kiosks Activity 1.4 — reproducibility package

This package contains reduced analysis-ready survey datasets, the city-specific harmonisation scripts, and a concise analysis script reproducing the core analyses used in the Activity 1.4 report.

## Folder structure

- `data/analysis_ready/`: six reduced, analysis-ready city datasets used by the reporting script.
- Full harmonised datasets should be retained internally and only released after a separate disclosure/privacy review.
- `scripts/harmonisation/`: city-specific scripts documenting how source datasets were mapped to the common schema.
- `scripts/report_analysis.py`: concise final analysis used for report tables and figures.
- `documentation/codebook.xlsx`: variable-level codebook for the harmonised datasets.
- `documentation/methodology_and_processing.md`: technical methodological decisions and data-processing notes.
- `outputs/tables/`: report and appendix tables generated by `report_analysis.py`.
- `outputs/figures/`: core figures generated by `report_analysis.py`.

## Reproduce the report analysis

From the package root:

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python scripts/report_analysis.py
```

## Scope of the clean analysis script

The script retains only analyses used directly in the final report: ownership and underutilisation, city-level extrapolations, sharing potential, pooled respondent-item GEE models, initiative adoption, and sharing-station motivations/barriers. Exploratory dashboard code, portfolio plots, conditional initiative-use heatmaps, and other development outputs were intentionally excluded from the reporting script.

## Important interpretation notes

City-level extrapolations are indicative and assume the survey sample approximates household ownership/use patterns in the wider city. Underutilisation is a study-specific operational definition. Borrowing willingness is stated intention, not observed future behaviour. The sharing potential index is a comparative prioritisation indicator, not a validated prediction of station performance.

## Data protection

Before public release, review the harmonised datasets for potentially identifying fields (e.g. postal codes, respondent IDs, open text). If the repository will be public, consider publishing a reduced analytical dataset containing only variables required by `report_analysis.py`.
